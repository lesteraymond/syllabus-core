## 1. Switch (the row §9a lacks)

| Switch | Adds | Prompt version with only this stage on |
|---|---|---|
| `SYLLABUS_CHECK_STAGE_C3` | Content-activity, Content-assessment, Activity-assessment (rules ALN-11, ALN-12, ALN-13) | `alignment-12c3-r8` |

- The stage is on only when the value is `on`. While it is off, `stageFlags()` has no `c3` key, so the flags, the report's `stages` and the prompt of every other configuration are unchanged. With every stage off the prompt is still `alignment-10`.
- With C1 and C2 also on, the prompt version is `alignment-12c1c2c3-r8`. With every stage on, it is `alignment-12ab34c1c2c3d1d2-r8-a8`: since 2026-10-30, Stage A's prompt revision 8 (its course-relevance scope no longer includes the course description) adds `-a8` whenever Stage A is on. The version is part of each answer's cache key, so no answer given under another version is reused for C3.
- Code: `stages.js` (switch and wording, `C3`), `lessonfit.js` (`chainRows`, `chainPairs`, `chainNotChecked`), `engine.js` (the Stage C3 block of `run()`), `verdict.js` (`CHAIN`), `answerReview.js` and `recommendationReview.js` (review notes).

## 2. The three relationships

| Type | Source | Target | Rule | Pair id |
|---|---|---|---|---|
| Content-activity | the lesson's course content, headed `Week <n> course content:` | the lesson's learning activities | ALN-11 | `row<i>-contentactivity` |
| Content-assessment | the lesson's course content | the lesson's assessment tasks | ALN-12 | `row<i>-contentassessment` |
| Activity-assessment | the lesson's learning activities, headed `Week <n> learning activities:` | the lesson's assessment tasks | ALN-13 | `row<i>-activityassessment` |

- **Which lessons.** Every lesson that is not an examination row and has any of the three texts (`chainRows`). The links are asked whatever the other answers say.
- **Each link is judged on its own.** Each has its own label, explanation, quotes and recommendation, so an aligned Activity-assessment link cannot hide a failing Content-assessment link.
- **No ILO.** Neither text contains an ILO, and the prompt tells the model never to raise or lower these labels because of one. The ILO relationships (ILO-content, ILO-activity, ILO-assessment) are unchanged. For ILO-assessment, see [the scoring review](ilo-assessment-scoring-review.md).
- **No rewrite.** `targetPath` is `null` and the types are in `NO_REWRITE`. The recommendation is one sentence saying what to change, and it is empty when the link is aligned. The faculty's text is never replaced.
- **Limits.** At most 36 lessons (`MAX_LESSON_PAIRS`), so at most 108 links per check. The links of further lessons are NOT_CHECKED (`not_asked`). Each text is cut at 2,000 characters.
- **When.** After the main pass and the B3, C1 and C2 passes, in requests of its own.

## 3. Advice only: what C3 can and cannot change

| Area | With Stage C3 on |
|---|---|
| Official score, deductions, pass mark 79, `passed`, `ready`, report `status` | **Unchanged.** The answer path treats the C3 types as advisory (`gemini.js` `ADVISORY_TYPES`, `isAdvisory`). A C3 answer gives 0 points and a `minor` SEM finding, and it never counts towards completion. |
| Scoring policy | **Unchanged.** `POLICY` stays `syllabus-policy-2`, and the C3 types are not in `POLICY.advisoryTypes`. The report's `hybrid.policy.advisoryTypes` adds them only for a check made with C3 on. `hybrid.scoring.official.policy` stays `syllabus-policy-2`. |
| Submission gate | **Unchanged.** The coded hard gates apply as before. By default (`SYLLABUS_CHECK_AI_GATE` unset) the gate is `advisory` and needs no AI result. Under `SYLLABUS_CHECK_AI_GATE=required`, the gate reads `hybrid.ready` and `verifiedAlignment()` (`service.js` `requireHybrid`), and neither looks at a C3 link. |
| Acceptance tier | `optional`, like every advisory type (`acceptance.js` `tierOfType`). |
| Verdict | ALN-11/12/13, category `activitiesAssessments`, listed only while C3 is on. NOT_ALIGNED is FAIL and PARTIALLY_ALIGNED is NEEDS_REVIEW. Both are always MINOR, with `recommendationType: 'REVIEW_REQUIRED'`. ALIGNED is PASS (INFO), shown as NOT_CHECKED while the scored check is incomplete, like every AI pass. A link with no answer is NOT_CHECKED (INFO), with no recommendation. |
| Advisory verdict summary | A failing C3 link counts in the verdict's own `alignment` and `overall` labels, as every other advisory stage's finding does. The panel is titled as advice (EN "Academic verdict (advisory)", TL "Akademikong hatol (payo lamang)"), and nothing in the submit path reads it. |
| Problem list | Each C3 problem carries the "advice only" pill (`hybrid.advisory`: EN "Reference · advice only", TL "Sanggunian · payo lamang"), because the report's policy lists the C3 types. |
| Other recommendations | C3 never adds a suggestion. A NOT_ALIGNED Content-assessment or Activity-assessment answer marks the lesson's tasks as invalid (`lessonfit.js` `assessmentInvalid`), as a failing ILO-assessment or Assessment-fit answer already does. That holds back the lesson's values rewrite (Value-use, and Module-value with D1). With D1 on, the lesson's values questions are not asked either (`values.js`, `valueClassification.js`). Points never change. |
| Order inside C3 | A C3 recommendation is withheld while the week's content is off the course (Stage B, `upstream_invalid`). An Activity-assessment recommendation is also withheld while the activities are off (`activity_invalid`). An off ILO does not hold either back. |

## 4. When a link is not checked

A link without a usable answer is never shown as a pass or a fail.

| Situation | The C3 links | `hybrid.alignment.stageC.c3` |
|---|---|---|
| Stage C3 off | not built, not asked; ALN-11/12/13 are not in the verdict | no `c3` entry |
| Claude cannot be used (the model is not approved, there is no key, or the provider refused or is blocked), or the main pass failed (for example 529, 500, a dropped connection) | not asked; ALN-11/12/13 are NOT_CHECKED | `skipped: 'ai_unavailable'` |
| The course is not in the official curriculum | not asked | `skipped: 'course_not_in_curriculum'` |
| No lesson has any of the three texts | none | `skipped: 'no_lessons'` |
| Only the C3 request fails: 529, 500, a dropped connection, 400, the 429 spend limit, a low credit balance, no answer before the deadline, a refusal, an answer cut at `max_tokens`, or a reply that is not JSON | every link INSUFFICIENT_EVIDENCE and `unverified`, with the provider's failure kind; NOT_CHECKED, with no recommendation | `notChecked` counts them |
| A link's answer is missing, or the answer contract refuses it (quotes not found in the texts; a claimed `targetPath`, tag or mapping; fields outside Claude's strict schema), and it is still missing or refused when asked again | that link NOT_CHECKED | `notChecked` |
| More than 36 lessons | the links of the further lessons are NOT_CHECKED (`not_asked`) | `notChecked` |
| An empty side (course content, activities or tasks) | INSUFFICIENT_EVIDENCE without a request (`insufficient_text`); NOT_CHECKED in the verdict | `noText` |

The explanation of a link with no answer says so: "The AI did not answer for this relationship (the provider call failed), so it has not been checked yet. Run the check again." No academic conclusion is drawn.

## 5. Nothing invented

- There is no rewrite target, so a C3 answer can never change the syllabus or offer a replacement text. The engine offers a suggestion only for an answer that has a `targetPath`.
- An answer that claims a `targetPath`, tags or a mapping is refused.
- An empty field is reported as missing. It is never filled in or judged.
- Each answer is reviewed offline, and a recommendation that reaches beyond the two texts is held back.

### Review notes (offline English word patterns)

| Code | Finds | Effect |
|---|---|---|
| `cites_outcome` | the explanation rests on an ILO, CLO, PO or EGA that neither text names | a caution on the finding; the verdict stands |
| `asks_for_outcome` | the recommendation asks the activities or tasks to address an outcome | recommendation withheld (`draft_review`) |
| `adds_scope` | the recommendation adds project or system scope that neither text states | recommendation withheld (`draft_review`) |
| `not_one_sentence` | the recommendation is longer than one sentence, or is a list | recommendation kept, with a caution (`draftWarnings`) |
| the resource codes shared with Stage C (`assumes_resource`, `proposed_resource`, `conditional_resource`, `resource_needs_confirmation`) | equipment, software, facilities or materials, judged against the two texts of the link only | as in §9g of the base |

The explanation checks of §9g (wording from another relationship, a reference to another week) also cover the C3 types. A recommendation is reviewed only when its link fails; a passing link shows none. The notes are shown in English and Tagalog (`src/i18n/hybrid.js`, `verdict.review.code.*`). They never change a label, a score or a gate.

## 6. Engine change (2026-10-29)

Before this change, Stage C3 was skipped for the whole syllabus whenever the scored check was incomplete only because some text was missing. That is failure kind `insufficient_text`: the provider answered, but a scored field, such as one lesson's activities or tasks, was empty. The report then said `ai_unavailable`.

Now C3 is still asked about the other links, and the links of the empty field are reported as `insufficient_text`. The change affects only checks made with C3 on. Checks with C3 off were compared before and after in 11 configurations and are identical. Stages C1 and C2 keep the old condition.

## 7. Evaluation

- **Dataset.** `server/lib/syllabuscheck/eval/stage-c3-dataset.json`, version `stage-c3-1`, holds 73 items from 30 lessons of three courses (IT 202, IE 402, CPE 304).
  - Types: 21 Content-activity, 23 Content-assessment, 29 Activity-assessment.
  - Expected labels: 29 ALIGNED, 10 PARTIALLY_ALIGNED, 20 NOT_ALIGNED, and 14 that accept either failing label.
  - 21 items are keyword traps.
  - Splits: 51 development, 22 held-out.
- **Not faculty-reviewed.** The lessons are synthetic and the labels author-written (`reviewStatus: unreviewed`). `facultyVerdict` is empty for every item, so the dataset measures nothing about agreement with faculty.
- **Offline runs.** `node --test server/lib/syllabuscheck/stage-c3-eval.test.js` checks the dataset. `node scripts/eval-alignment.cjs --provider anthropic --plan --dataset stage-c3` builds the requests and prints the worst-case cost, sending nothing.
- **Paid runs.** A run against a model is a paid call and needs approval. None has been made.

## 9. Known limits

- No live or paid run has been made, so how well a model answers these questions is unknown.
- The review notes are English word patterns. They do not read Filipino text, and they are heuristics, not verified findings.
- An outcome named in the same phrase as a negation ("so the CLO is not met") is read as set aside, so `cites_outcome` and `asks_for_outcome` miss it. Without the negation ("so it misses CLO 2") they catch it.
- No code check catches a recommendation that adds a topic neither text names; only the prompt forbids it.
- A C3 answer reused from an earlier check keeps the review notes it was stored with. The refresh of stored answers covers C1 and C2 only (`gemini.js` `refreshLessonDraftReview`). No C3 answer has been stored yet.
- With C3 on, the scored ALN-07 (ILO-assessment) and the advisory ALN-12 and ALN-13 can all advise on the same tasks field. See decision 3 of [the scoring review](ilo-assessment-scoring-review.md).
- Stages C1 and C2 still skip when a scored field is empty (§6).
